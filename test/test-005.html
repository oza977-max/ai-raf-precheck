7. Mutation testing

No project-wide mutation tool is configured, and none was installed. Targeted mutation was performed by hand on the two guarantees added this round, because a new test that cannot fail is worse than no test:

  • The attestation boundary. Letting STEP_BACK escape confirmation turns the guard test red. The boundary is protected, not merely asserted.
  • The tier sort. Deleting sortedById(policy.tiers) from evaluate() did not break the impact-dominance property — correctly, because tier selection takes the maximum and is order-independent by construction. What the sort protects is the tie-break between equal-tier rules, which random graphs never produce. A fifth property manufactures that tie, and it does go red when the sort is removed.
