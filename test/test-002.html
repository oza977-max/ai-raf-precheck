The D-001 fix

Double-clicking "Confirm and evaluate" wrote graph_confirmed twice to the append-only trail, produced no verdict, created no register node and stranded the user. Root cause: the guard was if (state.step !== 'confirmation') return, and dispatch() is asynchronous — two synchronous clicks read the same render's closure and both proceeded.

Fixed with a synchronous useRef flag, the pattern RegisterDetail already used. Verified three ways: the new test fails with the guard removed; the browser reproduction now yields exactly one of each event; and explore-002 re-tested it against the fixed build.

Releasing the guard on correction re-entry was itself missed and caught immediately by the existing P5-C01 test.

Honesty note on how VV-4(d) was cleared

ExploreDefect has no resolved field, so a fixed defect cannot be marked fixed inside an artefact. The only legitimate route was a fresh session whose artefact supersedes the previous one for gate purposes. explore-001.md was not edited — it remains the record of what was found. Downgrading a recorded defect to clear a gate would have been falsifying evidence in a product built to prevent exactly that.

Gap worth recording in the methodology: the contract can express "a Critical was found" but not "and it was fixed and verified". The only way to clear VV-4(d) is another full session, and the pressure that creates — to quietly edit the record — points the wrong way. A resolved: or fixed_in: field would close it.
