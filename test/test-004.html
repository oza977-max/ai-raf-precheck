7. Findings

Two findings survive. Under the stopping rule recorded in HANDOVER.md, neither blocks release: neither makes the product claim something untrue to a user, and neither breaks a core flow. Both are logged for V1.5.

PE-6 / RA-2 — “most demanding standard governs” is half implemented (MUST, V1 scope)
PE-6 states that track and tier assignments shall never be reduced below the jurisdictional minimum. Tier floors work and are tested. Track floors do not exist, and their absence is deliberate — src/engine/types.ts:205 records that track_floor is “intentionally absent — the supplement model was decided instead”. So the requirement's own fit criterion, a UK Track II overriding a US Track III, cannot be produced by the engine. Carried unchanged from verification 003.

Why it does not block: the product never claims a track floor was applied. It under-delivers against a requirement whose wording was overtaken by a design decision; it does not mislead. The honest fix is to amend PE-6 to describe the supplement model, not to build a capability that was reasoned away.

Second-order defect found here: the specs disagree with themselves about this. specs/evaluation-engine.md:182 says the track_floor effect type is removed; specs/evaluation-engine.html:450–453 and specs/policy-schema.html:608–755 still document it as live. This is exactly the .md/.html twin drift CLAUDE.md warns about, and spec-parity-check.py cannot see it because it reads only .md.
TC-PE-6-01, TC-RA-2-01 · src/engine/types.ts:205 · specs/evaluation-engine.md:182 vs specs/evaluation-engine.html:450
Four MUST property tests were specified and never written
TC-PE-PROPERTY-01 through 04 — jurisdiction monotonicity, impact dominance, hard-line supremacy, solver soundness — each name fast-check and a generation strategy. fast-check is not a dependency of this project and no generative test exists anywhere in src/. Verification 003 did not walk these four cases at all, so this is the first time they have been reported.

Why it does not block: each underlying property is covered by example tests in the same area — jurisdictional floors in jurisdiction.test.ts (16 passed), tier dominance in tier.test.ts (5 passed), hard-line precedence in evaluate.test.ts (23 passed), solver minimality in greedy-solver.test.ts (8 passed). What is missing is the universal quantifier, not the behaviour. These are the four highest-value tests still unwritten, because the engine's whole claim is determinism over a bounded space — precisely the shape property testing is for.
