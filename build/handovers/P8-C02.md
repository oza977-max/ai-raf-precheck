## Deviations from Spec
One, recorded deliberately. `intake-flow.md` §13.3 asks for `aria-required` on
every progress-blocking field. The jurisdiction question is a checkbox group,
and ARIA defines `aria-required` for form controls, not for `group` — there is
no conformant attribute for "this checkbox group must be answered". The
attribute is set on the `<fieldset>` with the marker in the legend, and the
compromise is documented in the code rather than presented as clean. Leaving
the question unmarked would have been the larger failure: it is the field most
likely to be outstanding, since P8-C01 made it the one that cannot be skipped.

## Retrospective
The interesting part was deciding what *not* to mark. Autonomy and the
replaces-something checkbox are in the gate's conjunction but open with a valid
answer, so marking them would tell the user nothing — and §13.3 rejects that as
firmly as marking nothing. But a draft written before those defaults existed
restores without them, which would leave an unmarked field holding the gate
shut with no way for the user to know. That is the defect the requirement
exists to close, arriving through the back door. `withDefaults()` is what makes
the honest answer ("these can never be outstanding") actually true rather than
merely usually true — and the realistic-fixture test is what forced the
question, since the happy path never produces that shape.
