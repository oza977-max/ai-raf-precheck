## Spec Gap Found and Resolved

`VerdictTraceData` (`verdict-audit.md §7`) wants `tripped_invariants: TrippedInvariant[]`
(plural, full set) and `controls_required: ControlDetail[]` (full control
records). But `Verdict` only exposes a single `binding_constraint` (the
ONE rule that determined the outcome) and `controls: string[]` (bare
IDs) — the full tripped-invariant list is computed internally by
`evaluate()` and discarded after step 6, never surfaced. **Resolution**:
`tripped_invariants` is a one-element array built from
`binding_constraint`/`binding_path`; `controls_required` looks up each ID
in `verdict.controls` against `policy.controls` for full records.
Documented in code comments, not silently claimed to be a complete
multi-invariant breakdown anywhere in the prompt or UI.
