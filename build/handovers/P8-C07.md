## Code Review Findings

**Review passes:** `[(1, 1), (2, 0)]`

**Pass 1 — 1 Important.** §15.1a requires the historical/current split to be
"labelled distinctly on the page so a reader can tell which is historical
record and which is current state". The split was correctly **sourced** — the
verdict from the persisted payload, evidence status from today's policy, with
TC-R3-RD-7-01 proving it — but it was **invisible**: the distinction lived only
in code comments, which a reviewer never sees. A reviewer watching a control
flip to UNVERIFIED had no way to tell whether that was the record or today's
state. Fixed with a visible line in the control-set panel, asserted in
TC-R3-RD-7-01.

Pass 1 also reported FN-003 missing from `specs/forward-notes.md` — and it was
right. An earlier edit of mine had used its heading as an anchor and swallowed
it. Restored and diffed against commit `e695936`: byte-identical.

**Pass 2 — 0 Critical/Important**, plus two lower-severity notes, both acted
on rather than deferred:

1. The "as of" line ended "…a status here can have changed since", which is
   trivially false on the submitter's screen seconds after evaluation. The
   component is explicitly dual-purpose, so the clause was dropped; what
   remains is true on both surfaces.
2. **With no policy loaded, the page said nothing about evidence at all** —
   just a plain id list. §15.1a is explicit that the status renders as
   *unknown* rather than UNVERIFIED, and silence is the same defect in the
   other direction: a reader cannot tell "we could not check" from "there is
   nothing to show". Now renders `EVIDENCE UNKNOWN` per control plus *"No
   policy is loaded, so whether evidence exists for these controls could not
   be checked. That is not the same as having no evidence."* Pass 2 classed it
   as pre-existing V1.3 behaviour and therefore out of scope; it is reachable
   from `App.tsx:135` whenever the policy file fails to load, and §15.1a is a
   round-3 section this chunk implements, so it was fixed here.

**One defect I introduced and caught myself.** `renderDetail(id, undefined)`
silently substituted the default policy, so the no-policy test exercised the
*with*-policy path while claiming otherwise. It is the same shape as P8-C05's
null-fixture near-miss: a test whose setup quietly makes its own claim true.
The helper now takes an explicit `null`.

## Retrospective
The chunk that closes charter 004's worst finding, and the review's one
Important was not about what the page shows but about what it fails to say
about itself. The data split was right; the reader had no way to know there was
a split. That distinction — sourced correctly versus communicated honestly — is
the same one that has now produced a finding in four consecutive chunks.

The no-policy state is worth naming too. Two reviewers looked at a page that
said nothing whatsoever about control evidence and classed it as acceptable
because it made no false claim. Saying nothing *is* the claim, when a reader
cannot distinguish it from having nothing to say. That is the third time this
round the same lesson has arrived wearing different clothes: the reasoning
chain, the empty invariant list, and now the evidence status.
