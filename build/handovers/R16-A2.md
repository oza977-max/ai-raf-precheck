## The zero-packs warning carve-out
`checkPolicyReferences` (A1) treats an unresolved `covers_reviews` id as an
**error** unconditionally. Once `CTRL-INDEP-VAL-01`'s
`covers_reviews: [SS1-UK-REV-01]` existed, every call site that loads the
real starter policy without also loading packs (seed scripts,
`PolicyEditor.test.tsx`, parts of `policy.test.ts`) started failing the
check, because a pack-only id now looked unresolvable with no packs in
scope. The fix, confirmed in the diff: when `packs.length === 0`, the same
unresolved ids are folded into **warnings**, each with an appended reason
("no rule packs are loaded, so it could not be checked against them");
with any packs loaded, resolution is real and an unresolved id stays an
error. TC-R16-A2-12 pins this exactly. I could not independently confirm
the specific count of tests broken before this carve-out was written — the
commit is atomic, and no intermediate failing-test state survives in git
history; recorded as briefed, not independently verified.

## The trace-check `## Superseded` mechanism (`23ac538`)
A new section type in any `test-cases/*.md` file: a `| TC-... | reason |`
table under a `## Superseded` heading. `trace-check.py` now parses it
(`SUPERSEDED_SECTION`/`SUPERSEDED_ROW` regexes), excludes those ids from
"untraced," prints each as `SUPERSEDED {id}: {reason}` on every run, and
**fails the check** if a superseded row has no reason. Built explicitly
"for the R16 form rewrite, which replaces the old field-by-field form" —
and used immediately: the very next commit (`d80307b`, chunks B+C/D1) is
the first to populate `## Superseded` sections, in
`test-cases-003.md`, `test-cases-015.md`, `test-cases-016.md` and
`test-cases.md` (two separate entries). See `R16-BC.md`/`R16-D1.md`.
