## Deviations from Spec

**One, and it is a spec error rather than an implementation choice.**
ADR-EE-R3-1 states the two conditions "can co-occur and both are then listed,
in a fixed order, satisfying R3-JU-6's 'where more than one applies, all shall
be stated'". Its own trigger definitions rule that out: `no_regulatory_basis`
fires when no pack activated, and `unsigned_pack_rules` fires when a fired pack
*rule* is unsigned — a rule cannot fire from a pack that never activated. The
two are **mutually exclusive by construction**, so TC-R3-JU-6-03's "both causes
present" is unreachable.

`test-cases-003.md` anticipated exactly this: *"If this combination is
unreachable in the current policy, the test is marked unreachable with a
recorded rationale rather than deleted."* The test asserts the mutual
exclusivity and records why. The ordering contract is asserted directly on
`PROVISIONAL_REASONS` so it still binds if a future trigger makes the pair
reachable. The collection stays ordered and plural for the same reason.

Worth flagging: my first draft of that test built the two-reason array **by
hand** and asserted its length was 2 — it would have passed against any
implementation whatsoever. It was rewritten before commit. That is the defect
class this project keeps hitting, and I nearly shipped an instance of it while
writing the tests meant to catch it.

## Upstream Fixes

1. **The register replaced the outcome with "Provisional".**
   `current_verdict_status` was set to `'provisional'`, discarding whether the
   case was in or out of appetite — directly contrary to `evaluation-engine.md`
   §13.3 ("Provisional is not a fourth status: it is a qualifier carried
   alongside the status"). Rare before round 3, universal after, which is what
   exposed it. The verdict screen's heading had the same defect. Both now carry
   the outcome and the qualifier together; `UseCaseSummary` gains
   `provisional: boolean` and the status union no longer accepts
   `'provisional'`. **The user was consulted and chose this over deferring it**,
   since it affects the page a 2LoD reviewer signs off from.
2. **`seedAigateSelfAssessment` never received the jurisdiction packs.** It
   called `evaluate(graph, policy)` with no packs while `AIGATE_USE_CASE_GRAPH`
   declares UK. Now takes a `packs` parameter, wired from `App.tsx`. A
   regression test asserts that supplying them removes `no_regulatory_basis`
   and that withholding them raises it.
3. Test fixtures across five files gained `provisional_reasons`, and two tests
   that encoded the replace-the-status behaviour were rewritten to the new
   contract.

## Retrospective

The chunk was specified as plumbing — move one boolean into the engine — and
the plumbing took an hour. The rest of the time went on consequences the spec
did not mention, and all of them came from the same place: making the condition
fire *often* turned three latent problems into visible ones. The register hiding
the outcome had been wrong since P6-C01. AIGate's self-assessment had been
scored without its own jurisdiction since P7-C01. The banner had no text for a
cause that barely ever fired. None of these were regressions; they were
pre-existing defects held below the waterline by a rare trigger.

The review loop is the thing I would defend. Pass 1 returned zero findings and
was wrong, and I only dispatched pass 2 because a clean first pass on a chunk
touching seven files was not believable. Pass 2 found the Critical by asking a
question pass 1 was never given: what does a user actually see now? Worth
carrying forward as a standing review question rather than a lucky prompt.
