## Code Review Findings

**Review passes:** `[(1, 0)]`

Clean on the first pass, with the user-facing question asked explicitly in the
prompt (added as standing practice after P8-C04's pass-1 false negative). It
verified `IntakeFlow.tsx` is the only production caller and does supply
`onCorrect`, that no other code path calls `onCorrect()` unguarded, and that
the exported helper is a pure scan carrying no evaluation logic out of the
store layer.

**One design note, raised and acted on rather than deferred.** Gating the
reasoning trace on `onCorrect` is a coincidental coupling: correction is a
submitter action, the trace is an optional retelling, and `{onCorrect &&
<details>Reasoning trace</details>}` reads as though the trace were a
correction concern. The reviewer judged it correct against today's spec and
did not raise it as a finding.

Acted on it anyway, minimally: the concept is now named
(`showSubmitterAffordances`) so the call site says what it means. A second prop
was **not** added — it would have had no consumer, which is the
computed-but-never-consumed pattern this project treats as a bug in waiting.
FN-004 records when to split them: the moment a caller genuinely needs one
without the other.

## Notes for Downstream Chunks

**P8-C07** now has both seams it needs:

- `VerdictDisplay` can be rendered without `onCorrect`; supplying neither it
  nor anything else yields a verdict with no correction control and no trace,
  which is TC-R3-RD-8-01's requirement.
- `findLatestVerdictEvent` is exported from `src/store/register.ts`. Use it —
  writing a third copy of that scan is the duplication ADR-EE-R3-1 exists to
  close, and I-4 called it out by name. It returns `undefined` for a trail with
  no verdict, which is the seeded AIGate self-assessment on every install and
  therefore C07's R3-RD-2 branch.

Also read **FN-003** before writing any absence-of-basis wording on the sign-off
page, and **FN-004** if you find yourself wanting the trace without correction.

## Retrospective
A twenty-minute chunk, and the only interesting decision was one the review
explicitly declined to raise as a finding. The reviewer was right that the
coupling is not a defect today and right that the prop name misleads. The
temptation was to resolve it by adding a second prop — which would have looked
like diligence and shipped an unused parameter into a component two more chunks
are about to build on.

Naming the concept costs nothing and makes the next reader's question
("why is the trace behind a correction handler?") answerable from the code
itself. The split is recorded as owed rather than performed, which is what
forward notes are for.
