## Spec Gaps Found and Resolved Before Implementation

1. **`ConfidenceCaveat` had no `confidence` field** — §5.3 requires
   checking `caveat.confidence === 'low' | 'medium'`, but the type (landed
   P3-C01) only had `{ruleId, field, reason}`. **Fixed**: added
   `confidence: 'low' | 'medium' | 'high'`. `evaluate()` still doesn't
   populate `confidence_caveats` with real data (always `[]`) — RA-11
   rendering is built and tested against synthetic `Verdict` fixtures, not
   engine-produced ones. Flagged for a future engine chunk.
2. **§5.2's "`Verdict.reasoning_trace`" doesn't exist on `Verdict`** —
   reasoning trace actually lives on the `verdict_produced`/
   `verdict_corrected` audit event's `payload.reasoning_trace` per §5.4/§7.
   `VerdictDisplay.tsx` reads it from the matching audit event, correctly.
3. **`reasoning-trace.ts` (P5-C02) doesn't exist yet** — the `<details>`
   section always falls back to the structured summary (rule ID + policy
   description), per §5.4's own designed degradation path, not a gap.

## Surfaced Requirements

**The register `label`-staleness gap** (see Code Review Findings) —
worth a follow-up ticket, not urgent.

**Pre-existing gap found during live verification (not introduced by
this chunk, not fixed here):** `handleConfirmAndEvaluate()` (pre-dates
P5-C01, present since P4-C04) does `throw new Error(...)` on an
`EngineError` (e.g. `no-track-match`) with no `try/catch` anywhere in the
call chain. Live-tested with a structured-form input combination that
legitimately has no matching track rule (`traditional-ml` +
`non-binding`, correctly rejected by the engine) — the UI silently gets
stuck on "Evaluating…" forever with no error message, no console log
visible to the user, nothing actionable. The underlying engine behavior
is correct (verified via `window.onunhandledrejection`: `"Error:
Evaluation failed: no-track-match"`); the gap is purely UI error-handling.
Worth a small follow-up chunk: catch this and render an error state,
similar to the existing `extractionError` pattern already used for LLM
extraction failures.
