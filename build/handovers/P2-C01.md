## Retrospective

**Harder than expected:** discovering that the pre-existing `policy/appetite.yaml` (committed
before tech-spec) used a completely different, non-matching schema — this required a build-prep
fix to the implementation guide itself (done before this chunk was prompted, in commit 4983a8f)
plus a full regeneration as part of this chunk's work, rather than a simple "replace the stub
function" task.

**Easier than expected:** the Zod-schema-as-single-source-of-truth pattern from the Framework
Reference mapped cleanly onto the `PolicyFile` interface with minimal friction — writing the
validation logic was straightforward once the schema drift was resolved.

**What I'd do differently:** the round-trip self-check that caught the `regulatory-reporting`
misclassification should probably be promoted to an explicit, permanent test case (not just an
ad hoc check during self-review) — flagging as a possible `TC-CF-5-0X` addition for a future
test-cases round, since "does the shipped starter config actually validate against its own
schema" seems like a test worth keeping rather than a one-off sanity check.
