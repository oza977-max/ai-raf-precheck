## Spec Boundary Confirmed Before Implementation

`register-lifecycle.md §10.3` describes an "Export JSON" button as part of
`RegisterView.tsx`, but the wiring matrix assigns `RegisterStore.exportAll()`'s
consumer call site to **P7-C02**. This chunk does not build the export
button — confirmed out of scope, not an oversight.

## Real Gaps Filled (not deferred)

1. **Role storage** — `src/store/role.ts` (new), a thin
   `localStorage['aigate:role']` wrapper (`getRole()`/`setRole()`, default
   `'1LoD'`). The one deliberate exception to this build's running pattern
   of deferring auth/role work, because the register view's entire purpose
   (1LoD vs 2LoD visibility) depends on it.
2. **`UseCaseSummary`'s verdict-derived fields** — `current_verdict_status`,
   `last_evaluated_at`, `policy_version_at_evaluation`, `stale_assessment`
   were always `null`/`false` since P2-C02. Per `verdict-audit.md §8`'s
   explicit architectural principle ("computed by scanning `AuditEvent[]`,
   not persisted separately"), `getUseCases()`/`getUseCase()` now scan each
   use case's audit trail (most recent `verdict_produced`/`verdict_corrected`
   event) to compute these for real.

## Documented Deviation

`stale_assessment` compares `policy_version_at_evaluation` against the
CURRENT loaded policy's version (a real, populated field), not "active pack
versions" — jurisdiction packs still don't exist in this codebase (same
unresolved deviation since P3-C01).
