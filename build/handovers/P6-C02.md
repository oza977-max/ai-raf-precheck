## Spec Drift Found and Resolved

Four documented resolutions — full detail in `build/prompts/P6-C02.md`:

1. `register-lifecycle.md §7`'s richer `tier_workflows` YAML shape
   (`governance_path`/`verdict_is_final`/`twoLoD_notification`/etc) was
   never implemented by P2-C01's Zod schema — the real schema is
   `tier_workflow: Record<Tier, WorkflowType>` where `WorkflowType` is a
   bare string (`"self-service"` / `"2LoD-notify"` / `"2LoD-approve"`).
   `routeToWorkflow()` is built against the real schema; the 5-day
   review-window value from §7's example is a hardcoded constant since
   the real schema carries no such field.
2. `onPolicyUpdated()` takes only `newVersion: string` and imports
   `register.ts`/`audit.ts` directly instead of the spec's injected
   `RegisterStore`/`AuditStore` interface params, which don't exist as
   types anywhere in this codebase (matches the existing
   `register.ts → audit.ts` store-to-store import pattern).
3. The impl-guide wiring matrix lists `workflow-router.ts`'s "Demanded
   by" chunk as P6-C01, which already shipped without it — a
   chunk-ordering inconsistency in the impl guide, not fixed
   retroactively.
4. Apparent tension between the impl guide's P6-C02 deliverable list
   (wiring `updateLifecycleStage()` into intake/verdict flows now) and
   its P7-C03 closure checklist (re-verifying that same wiring) —
   resolved by reading P7-C03's line as a standard integration-closure
   re-audit (same pattern already used for P5-C02's reasoning-trace
   wiring and P6-C01's stale badge), not a deferral. TC-LC-1-01/2-01/2-02
   require the real wiring to pass, so it's built now.
5. The register node doesn't exist until the first confirm+verdict cycle
   (established since P4-C01/P5-C01) — the Idea/Exploring states are
   unobservable. The node is created directly at its routed stage instead
   of a hardcoded `'idea'`.
