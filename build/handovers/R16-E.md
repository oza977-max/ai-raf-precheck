## Deviations from the contract, and decisions the contract left to me

- **`fillPlaceholders` (`verdict-view-model.ts`) exported, not duplicated.**
  Not in the contract's own file list. `QuestionnaireStep`'s new "why we ask"
  line needs the same `{audience}`/`{destination}` resolution the verdict
  screen already has; adding a second implementation would violate
  "one computation per fact" more than widening this function's visibility
  does. Minimal, one-line change (`export` added to an existing function).
- **`isVendorOrModel` field-name override in `QuestionnaireStep`.** Neither
  `vendor` nor `declared_model_id` has a closed canonical vocabulary
  engine-side, so the generator emits them as `answer_type: 'text'` — but
  §2's contract text clearly wants select-like UI (named options, "Not on
  the list", "I don't know"). The contract doesn't say how to reconcile an
  engine-side `'text'` type with form-side structured choices, so I added a
  field-name check that takes priority over the generic `answer_type`
  switch. Confirmed by E2E tests driving both fields through their option
  lists and follow-up text questions.
- **The §8 guard test is per-screen, not one shared fixture sweep.** The
  contract describes it as rendering five things "from fixtures" and
  asserting one banned-word list; I judged that a single mega-test coupling
  all five components' fixtures together would be more brittle (one
  component's unrelated change breaks everyone's guard) than the same list
  duplicated at the bottom of each component's own new test file. Every
  component's guard scan uses the identical banned-word regex from the
  contract's §8 text.
- **`test-cases-015.md` gained a `## Superseded` row for `TC-R15-C3-05`'s
  sibling, `TC-R15-C5-01`, not a new test adaptation.** That case's entire
  premise — a field row showing the plain label with the engine field name
  still present as a `<code>` beside it — is reversed by D-103's "no code
  beside any label." I deleted the dedicated test block (its replacement
  fact, the label with no code anywhere, is `TC-R16-E-41`/`-41b`), then
  found `trace-check.py` was satisfied anyway by an incidental code-comment
  mention of the old id elsewhere; rather than rely on that accident, I
  added a proper `## Superseded` row explaining why, and regenerated the
  `.html` twin.
- **Found and fixed while verifying, not caught by planning:**
  - The `App.css` narrow-window rewrite was planned but the edit itself was
    initially skipped — caught only because my own new test
    (`TC-R16-E-50`) failed against the unmodified file. Fixed by making the
    actual CSS change (flex-column stack, rotated arrow) described above.
  - My first pass at the review screen's "Fix guessed values" button broke
    my own §8 guard scan — "guessed" is on the banned-word list. Renamed to
    "Fix the details we couldn't tell" and updated the one pre-existing
    test asserting the old string (`GraphReview.r9.test.tsx`).
- **Pre-existing tests broken by an accidental coupling, not a regression in
  behaviour.** Removing the jurisdictions panel's `"— confirm"` button
  suffix broke ~6 tests that were never testing jurisdiction-confirmation on
  purpose — they relied on a shared `/confirm$/i` click-loop also happening
  to match that button as a side effect. Fixed by adding explicit
  jurisdiction-confirm clicks to `GraphReview.r5.test.tsx`,
  `GraphReview.r6.test.tsx`, and extending `WalkingSkeleton.test.tsx`'s
  shared `confirmAllNodes` helper to confirm jurisdictions generically
  (fixing 7 tests at once there). No product behaviour changed by this fix;
  only the tests' own confirmation sequence.
