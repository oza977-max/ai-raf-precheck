### UC-2/RG-2 duplicate-match redaction (`IntakeFlow.tsx`)

Fixed a real information leak the design had explicitly guarded against:
the old LLM-confirmed duplicate warning showed the matched use case's
LABEL to any role. Now a `duplicateMatch {tier, label}` state feeds one
card:
- **Non-2LoD**: redacted — "A use case with overlapping characteristics
  — tier {tier} — is already on record. Full detail is visible to the
  2nd Line of Defence. Contact AI Risk to adopt its classification, or
  confirm yours is genuinely new." The label is structurally unreachable
  in the DOM (conditional rendering, not CSS — BC-V12C-02,
  review-traced including title/aria attributes and console paths).
- **2LoD**: full detail including the matched label.
- Both the keyword path (which previously showed no tier at all) and
  the LLM-confirmed path feed the same card.

Documented deviation: the design gates the flow on an explicit "This is
a new use case →" click at a dedicated duplicate step; our state machine
auto-proceeds (P4-C01 design) with the card visible during graph review.
A real gate is a reducer change — listed for a future chunk.

## Code Review Findings

**Review passes:** [(1, 1), (2, 0)]

Pass 1 — 1 Important: **the NF-10 banner was a permanent false positive
after genuine adoption.** `yaml.includes('[FIRM]')` also matched the
template's own instructional comments ("Search for [FIRM] markers
below…"), so a CRO who filled in every real field but kept the template
header would see "verdicts are provisional" forever — an integrity
defect in a product built on honest status claims. **Fixed**: comment
lines stripped before the check + regression test. Pass 2 verified the
fix and judged the heuristic right-sized (inline trailing comments still
over-warn — errs conservative; quoted-value markers still trigger — the
intended true positive). Converged, zero findings.
