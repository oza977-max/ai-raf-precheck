## Deviations from Spec

1. **Package version bumps past `cross-cutting.md §2` pins** — `vite ^5.4.8 → ^8.1.3`,
   `vitest ^2.1.2 → ^4.1.10`, `@vitejs/plugin-react ^4.3.2 → ^6.0.3`, `uuid ^9.0.1 → ^14.0.1`.
   Rationale: `npm audit` on the spec-pinned versions found 1 critical (Vitest UI server
   arbitrary file read) + 1 high (Vite path traversal in optimized deps) + 4 moderate,
   all dev-tooling-only (no production/`dist/` exposure since AIGate ships as a static
   bundle with no dev server). Zero-vulnerability versions were available at install time;
   took them at chunk 1 rather than inherit known CVEs into the foundation every later
   chunk builds on. `uuid` v14 dropped `@types/uuid` (ships its own types) — removed that
   dev dependency accordingly.
2. **`vite.config.ts` `manualChunks`: object form → function form** — Vite 8's new Rolldown
   (Rust) bundler rejects the legacy Rollup object-map form (`TypeError: manualChunks is not
   a function`). Converted to the function form; same chunking intent (`vendor` = react/react-dom,
   `engine` = uuid).
3. **Test environment fix, not in any spec** — two real environment bugs, not spec drift, fixed
   during this chunk:
   - jsdom needs `environmentOptions.jsdom.url` set (e.g. `'http://localhost/'`) to enable the
     Web Storage API; without it, `localStorage` is `undefined` in the jsdom test DOM.
   - Node 26 ships its own native experimental `localStorage` (`--webstorage` flag family) that
     shadows jsdom's polyfill even when `environment: 'jsdom'` is set. Fixed via
     `NODE_OPTIONS=--no-experimental-webstorage`, baked into the `test`/`test:watch` npm scripts
     via `cross-env` (added as a new devDependency) for cross-platform portability.
4. **cross-cutting.md `src/ui/*` → `src/components/*` fixed pre-chunk (build-prep, not this
   chunk's deviation)** — see commit 78314d0. Documented here for completeness since this
   chunk's file layout depends on the corrected convention.

## Retrospective

**Harder than expected:** the jsdom/Node 26 `localStorage` interaction. Node 26 is very recent
(shipped its own experimental native Web Storage implementation) and its shadowing behavior
against jsdom's polyfill is not yet a well-documented gotcha — took real debugging (checked
jsdom directly, then found the Node CLI flag) rather than being a quick spec-lookup fix. Also
non-obvious: Vite 8's switch to the Rolldown bundler broke the `manualChunks` object-form API
that `cross-cutting.md §8` specified — the spec was written against Vite 5's Rollup-based
config, and the newer major version changed the contract.

**Easier than expected:** the actual boundary-wiring logic (IndexedDB round-trip, Anthropic
`tool_use` call) was straightforward once the environment issues were resolved — `idb`'s typed
API and the Anthropic SDK's `tool_choice: { type: 'tool' }` forcing are both well-designed and
matched the Framework Reference in the prompt closely.

**What I'd do differently:** run `npm audit` immediately after the first `npm install`, before
writing any application code — would have caught the version-bump decision earlier in the
chunk rather than after most of the boundary code was already written against the
spec-pinned versions (though in practice no rework was needed since the APIs used are stable
across the version bumps).
