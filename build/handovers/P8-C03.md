## Upstream Fixes

Three, all found by this chunk and all pre-existing.

1. **`TC-R3-JU-1-04` had no test.** P8-C01 recorded its coverage as
   `TC-R3-JU-1-01…-05` and the case for "the three answered-states are
   distinguishable from persisted state" was never written. Found by
   cross-reading every `TC-R3-*` id in `test-cases/test-cases-003.md` against
   the ids present in `src/`, not by re-reading the handover. Test added here;
   it asserts all three states are distinct AND that "not answered" is not
   inferred from an empty selection — states 1 and 2 both persist `[]`.

2. **The P8-C02 acceptance test was a latent timeout flake, and I wrote it.**
   `TC-R3-JU-5-01` re-renders the form 18 times, and driving each render with
   `userEvent` (which simulates every keystroke) left it just inside the 5s
   limit. It passed three consecutive runs at commit time and began failing as
   soon as the machine was busy. The probes now use `fireEvent`: 3.7s for the
   whole file, down from 6.5s. The assertions are about one button's disabled
   state, not about typing, so the cheaper event is the honest one here; tests
   that genuinely exercise user interaction still use `userEvent`. Re-mutated
   afterwards (renaming `sf-scale`'s `controlId`) to confirm the faster probe
   still catches marker/gate drift — it does.

3. **Agent worktrees were doubling the test suite.** A background task created
   `.claude/worktrees/<name>/`, a full copy of the repo including its tests.
   `npm test` then reported 577 tests instead of 286 and both copies competed
   for CPU, which is what pushed the flake above over its timeout — a code
   failure that was nothing of the kind. `vite.config.ts` now excludes
   `.claude/**`. This belongs in the same family as the `npx vitest` trap
   already documented in `CLAUDE.md`: a green suite reading red for reasons
   outside the code.

4. **Four test cases were allocated to no chunk at all.** TC-R3-RD-2-03, -6-01,
   -7-01 and -8-01 were each added to `test-cases-003.md` by design review round
   1 (findings I-10, I-2, C-2, I-1) and never written back into the
   implementation guide's chunk table when the review's findings were folded
   into the specs. All four now have owning chunks (§11.2a). Notably
   TC-R3-RD-8-01 is the case that tests P8-C06's entire deliverable, and P8-C06
   had been left pointing at TC-R3-RD-4-01, which is a whole-page assertion
   belonging to P8-C07.

## Retrospective
FN-001 was right, and that was the least interesting thing about the chunk. The
value came from taking "confirm no further edge case is open" literally: a
coverage claim in a handover is exactly the kind of statement BC-001 exists to
distrust, and checking it took one command and found a missing test plus four
orphaned test cases.

The flake is the part I would do differently. I ran the P8-C02 suite three
times, per the project's own ordering rule, and it passed three times — the
rule caught nothing because the failure mode was load, not order. A test a
second away from its timeout is not passing, it is winning a race. Worth
watching wall-clock, not just the exit code.
