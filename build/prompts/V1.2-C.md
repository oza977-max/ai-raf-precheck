## Origin

Third chunk of the design-gap plan (`build/design-gap-audit.md`).

## Scope

### D1–D4 — PolicyEditor becomes the design's Appetite Framework view

Current state: bare textarea + Validate/Save (P7-C03). Additions:

1. **Header**: "Appetite framework" title, "policy v{version} · {n}
   jurisdiction packs declared" subtitle, and the design's framing line
   ("The bank's rules, machine-readable and versioned. Every verdict
   traces back to a rule in here. The engine enforces it — it does not
   invent it.").
2. **NF-10 ACTION-REQUIRED banner**: shown when the current YAML
   contains `[FIRM]` markers — "Starter config in use. [FIRM] markers
   and translation-fidelity attestation are unfilled — verdicts are
   provisional until your CRO adopts this framework (NF-10)." Detection
   is a plain substring check on the YAML text (the markers are the
   template's own convention).
3. **Dark YAML panel**: the textarea restyled as the design's dark mono
   code panel. Deviation, documented: the design shows a syntax-
   highlighted read-only panel; ours must remain EDITABLE (the P7-C03
   save flow is the whole point), and overlay-based highlighting inside
   a textarea is fragile complexity for zero governance value — dark
   mono styling only.
4. **Jurisdiction packs panel**: rows from the parsed policy's
   `jurisdictions` (code, name, pack files). Status chip is the honest
   one — **"declared — not loaded by V1 engine"** for every pack — NOT
   the design's fired/loaded states, which require pack loading (a V2
   capability; claiming "loaded" would be a lie the audit explicitly
   guards against).
5. **Hard-lines panel**: "HARD LINES — NO CONTROL SET CAN FIX / Checked
   first. A use case crossing one is rejected immediately (PE-4)." with
   each hard line's id + description from the parsed policy.
6. **Live panels**: header/banner/packs/hard-lines derive from the
   CURRENT textarea content via a `useMemo` parse (loadPolicy is pure);
   while the YAML is invalid the panels show the last… no — simpler and
   honest: panels render only while the current text parses valid;
   invalid text shows a one-line "panels unavailable — YAML invalid"
   note (the Validate button gives field-level errors).

### C1 — UC-2/RG-2 redacted duplicate-match card

Current behavior is a real leak: the LLM-confirmed path shows the
matched use case's LABEL to any role ("A similar use case may already
exist: '{label}'"), violating the UC-2 fit criterion (repo-updates
§6.1: 1LoD sees a redacted match — tier only; full detail is 2LoD-only).

Replace the `duplicateWarning` string state with a
`duplicateMatch: { tier: string | null; label: string } | null` and a
match card rendered where the warning was (graph review step):
- **Non-2LoD**: "One similar use case exists in the register — tier
  {tier}. Full detail is visible to the 2nd Line of Defence. Contact AI
  Risk to adopt its classification, or confirm yours is genuinely new."
  The LABEL IS NEVER RENDERED for 1LoD.
- **2LoD**: same card plus the matched label.
- Both the keyword-only path and the LLM-confirmed path feed the same
  card (the keyword path previously showed no tier at all).

Documented deviation: the design gates the flow on an explicit "This is
a new use case →" click at a dedicated duplicate step; our state machine
auto-proceeds (P4-C01 design) and the card stays visible during graph
review. Making the gate real is a reducer/state-machine change — out of
scope here, listed for a future chunk.

## Known Patterns to Avoid

- BC-V12C-01: pack status must never claim "loaded"/"fired" — the V1
  engine does not load packs; the chip text states that plainly.
- BC-V12C-02: the matched use case's label (or any field beyond tier)
  must be UNREACHABLE in the DOM for non-2LoD roles — not CSS-hidden.
- BC-V12C-03: PolicyEditor's Validate/Save behavior (P7-C03) unchanged —
  panels are additive.
