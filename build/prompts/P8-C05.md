# Build Prompt: P8-C05 — The verdict states the consequence and the cause

## Chunk Summary

Where no regulatory basis was applied, the verdict must carry **two distinct
things**, because they address two readers:

| | R3-JU-3 — the consequence | R3-JU-6 — the cause |
|---|---|---|
| Reader | The submitter, now | A later reader of the record |
| Form | Prose, in the verdict body | A labelled reason on the verdict |
| Says | "No regulatory rules were applied, so there are no citations" | `no_regulatory_basis` |

An implementation providing one has met one requirement, not both
(TC-R3-JU-3-02 fails exactly one assertion in that case, not both and not
neither).

## Spec Excerpt

`verdict-audit.md` §13.1 (verbatim):

> Before round 3, a verdict with no active packs simply had no REGULATORY
> REASONING CHAIN panel. A reader could not distinguish "no regulation applies
> here" from "we did not check" from "the panel failed to render". All three
> look identical: nothing.
>
> R3-JU-3 requires the explanation to be **present**, not the panel to be
> absent.

§13.2: the two reasons "must be textually distinguishable, not merely both
present under one 'Provisional' banner. A reader must be able to tell, without
opening the policy, whether rules were applied and not yet adopted, or not
applied at all."

§13.2a (I-6) — **invariant:** all content sourced from `PolicyFile` or a
`JurisdictionPack` is rendered as plain text through JSX child interpolation.
`dangerouslySetInnerHTML` and any markdown/HTML renderer are prohibited on
those fields.

**Verified current behaviour (BC-001):** the panel is gated on
`explanation?.regulatory_chain && explanation.regulatory_chain.length > 0`
(`src/components/VerdictDisplay.tsx:356`) — when the chain is empty the whole
block renders nothing at all, which is precisely the defect §13.1 names.

## Test cases

- **TC-R3-JU-3-01** — an explicit statement is present; the chain is not merely
  omitted.
- **TC-R3-JU-3-02** — the prose statement and the labelled reason are each
  independently assertable; neither satisfies the other's assertion.
- **TC-R3-JU-3-03** — a verdict with active packs carries no such statement.
- **TC-R3-JU-6-01, -02, -04** — the labelled cause, its distinctness, and its
  absence when not provisional (applied to C04's existing tests).
- **TC-R3-JU-6-03** — both causes at once. **Unreachable**: C04 established the
  two triggers are mutually exclusive by construction (a rule cannot fire from
  a pack that never activated), contradicting ADR-EE-R3-1's claim that they can
  co-occur. Per `test-cases-003.md`'s own instruction, mark unreachable with a
  recorded rationale rather than delete.

## Framework Reference

- React 18 / JSX interpolates children as text — the §13.2a invariant holds by
  default; the requirement is not to break it.
- Testing Library: assert the two surfaces separately by scoping —
  `getByRole('alert')` for the banner, and a scoped query or test id for the
  body statement. A single unscoped `getByText` that both could satisfy would
  defeat TC-R3-JU-3-02's entire purpose.

## Review Criteria (self-review loop)

- **Leveson:** does any path still communicate absence by absence?
- **Beck:** would TC-R3-JU-3-02 fail if only one of the two were implemented?
  If a single element satisfies both assertions, the test is not doing its job.
- **Honesty:** the firm's own policy *did* apply. No string may imply nothing
  was assessed.
- **HR3-08:** no new rendered string contains "approved" or "rejected".
- **§13.2a:** no `dangerouslySetInnerHTML`, no markdown renderer, on any
  policy- or pack-sourced field.

### Known patterns to avoid (build checks)

- **BC-001** — cite `file:line` for every claim about existing code.
- **Computed but never consumed** — C04's Critical was exactly this. Anything
  rendered here must have a test asserting a reader sees it.
