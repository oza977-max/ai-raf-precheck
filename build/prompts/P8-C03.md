# Build Prompt: P8-C03 — Draft migration (R3-JU-7)

## Chunk Summary

A saved intake draft created before round 3 must load with the jurisdiction
question **unanswered**, whether its `jurisdictions` array is empty or
populated. The populated case is the dangerous one: it looks answered.

**FN-001 (specs/forward-notes.md) governs this chunk.** P8-C01 discharged the
behaviour by construction — the draft envelope means a bare pre-round-3 values
object carries no answered-state and loads as `'unanswered'` without a special
case. This chunk therefore **adds the trace IDs, confirms no further edge case
is open, and closes. It does not re-implement the migration.** If a genuine gap
is found, it is recorded rather than silently rebuilt.

## Spec Excerpt

`intake-flow.md` §13.4 (verbatim):

> `loadFormDraft` may return a draft persisted before round 3, carrying a
> `jurisdictions` array and no answered-state. Such a draft loads as **not
> answered**, regardless of whether its array is empty or populated.
>
> The populated case is the dangerous one and the reason this is a requirement
> rather than an implementation note: a draft with `["UK"]` already in it looks
> answered. Accepting it would re-open the round-3 defect for every user
> holding a draft, invisibly — they would never see the question they had not
> answered.

R3-JU-7 (Must) — fit criterion: a draft persisted without an explicit
answered-state loads with the jurisdiction question unanswered and Continue
unavailable.
