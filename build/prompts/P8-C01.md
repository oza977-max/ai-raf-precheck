# Build Prompt: P8-C01 — Jurisdiction answered-state

## Chunk Summary

The guided intake form offers six jurisdiction checkboxes but requires no
answer: the completeness predicate tests the selected set for presence only,
and an empty array is truthy. A user can proceed with nothing ticked, attest to
a graph reading "JURISDICTIONS — None specified", and receive a verdict with no
packs, no regulatory chain and no citations, with nothing telling them.

This chunk makes the question answerable and required. It is the MVP-1 slice of
Phase 8: a user is asked something, cannot proceed without answering, and the
answer reaches the graph the engine evaluates.

## Spec Excerpt

**`intake-flow.md` §13.1 — the three answered-states**

| State | Selected set | Continue | How reached |
|---|---|---|---|
| Not answered | `[]` | **Disabled** | Initial state of a new form; a pre-round-3 draft |
| Answered: none | `[]` | Enabled | User explicitly chooses "none / not sure" |
| Answered: selected | one or more codes | Enabled | User ticks at least one jurisdiction |

Deselecting the last ticked jurisdiction returns the question to **answered:
none**, not to *not answered* (TC-R3-JU-1-05). A user who ticks and unticks has
engaged with the question; silently returning them to a blocked state with no
explanation would be a worse defect than the one being fixed.

**Field shape, pinned by design review 002 (I-7):**
`jurisdictionAnswer: 'unanswered' | 'none' | 'selected'`, held in the form's own
state and its persisted draft, **alongside** `Partial<StructuredFormValues>` and
not inside it — `buildGraphFromForm` consumes `StructuredFormValues` and must
not see a form-only concern (ADR-IF-R3-1).

**`intake-flow.md` §13.2 — the control.** Rendered inside the same fieldset, not
as a separate question. Choosing "none / not sure" clears any selected
jurisdictions; ticking a jurisdiction clears it. Mutually exclusive by
construction, not by validation.

**§13.2 / R3-JU-4 — help text** states that the answer determines which
regulatory rules are applied.

**ADR-IF-R3-1 consequence.** `buildGraphFromForm` continues to emit
`jurisdictions: string[]`, unchanged. "Answered: none" emits `[]`. The engine's
input contract is untouched.

## TDD Approach

This is a user-facing chunk. TDD-1 applies: the outside-in acceptance test is
the **first** deliverable.

1. **Acceptance test (first).** Render the form, fill every other required
   field, touch nothing in the jurisdiction fieldset, assert Continue is
   disabled. Then choose "none / not sure" and assert Continue enables. Confirm
   **Red**, capture the SHA.
2. Unit tests, driven by the acceptance test's failures:
   - ticking a jurisdiction enables Continue
   - ticking a jurisdiction clears "none / not sure"
   - choosing "none / not sure" clears selected jurisdictions
   - **realistic-fixture variant (TDD-3):** tick UK then untick it — the
     question stays *answered: none*, Continue stays enabled. This is the path a
     real user takes and the one a happy-path test misses.
3. Confirm acceptance test **Green**, capture the SHA.

## Review Criteria (self-review loop — not construction)

- **Beck:** every behaviour has a test that demanded it. No code without a

- **McConnell:** the three states are named in the type, not inferred from

### Known patterns to avoid

- **The empty-array trap.** `isComplete` currently tests `v.jurisdictions` for
  presence; `[]` is truthy. Do not fix this by testing `.length > 0` — that
  would block the legitimate "answered: none" case and re-break the user in the
  opposite direction.
- **Rendered strings.** Avoid the words "approved" and "rejected" in any new
  rendered string; existing UI tests use a single-match `/approved|rejected/i`
  query.
