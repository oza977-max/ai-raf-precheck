# Build Prompt: P6-C01 — Register View (1LoD + 2LoD + Role Access)

## Chunk Summary

`src/components/RegisterView.tsx` — the register list screen, real for
the first time (previously just a bare 2-column table inline in
`IntakeFlow.tsx`). Two views (1LoD: own use cases; 2LoD: all use cases),
role-filtered at the store layer, filter chips + search (2LoD only),
stale-assessment badge, wired to the sidebar's previously-decorative
"Register" nav item. User-facing — **TDD-1 applies.**

## Spec Boundary Confirmed Before Implementation

`register-lifecycle.md §10.3` describes an "Export JSON" button as part
of `RegisterView.tsx`, but `implementation-guide.md`'s wiring matrix
explicitly assigns `RegisterStore.exportAll()`'s consumer call site to
**P7-C02**, not P6-C01, and P6-C01's own deliverable list doesn't mention
export at all. **This chunk does not build the export button** — that's
P7-C02's scope. Confirmed via the wiring matrix, not guessed.

## Real Gaps Filled (not deferred, genuinely in scope here)

1. **Role storage didn't exist anywhere** — `CURRENT_ROLE` was a hardcoded
   `'1LoD'` constant in `IntakeFlow.tsx`. This chunk's spec explicitly
   requires `localStorage['aigate:role']`-driven role switching for
   register visibility (§10.1/§10.2), so a real `src/store/role.ts`
   (`getRole()`/`setRole()`) is built here — **this is the one exception**
   to this build's running pattern of deferring auth/role work, because
   the register view's entire purpose (1LoD vs 2LoD visibility) depends
   on it. `IntakeFlow.tsx`'s `CURRENT_ROLE` constant is replaced with
   `getRole()` calls. A simple role-switcher control is added to the app
   header (matching the design export's 1LoD/2LoD toggle).
2. **`UseCaseSummary`'s verdict-derived fields were always `null`/`false`**
   (`current_verdict_status`, `last_evaluated_at`,
   `policy_version_at_evaluation`, `stale_assessment` — P2-C02's
   placeholder comment literally said "land with the real engine wiring").
   Per `verdict-audit.md §8`'s explicit architectural principle ("computed
   by scanning `AuditEvent[]`, not persisted separately"), `getUseCases()`/
   `getUseCase()` now scan each use case's audit trail (most recent
   `verdict_produced`/`verdict_corrected` event) to compute these for
   real. N+1 audit query per use case — acceptable at V1 scale (small
   register), documented as a known scaling limit, not silently ignored.

## Documented Deviation

**`stale_assessment` compares `policy_version_at_evaluation` against the
CURRENT loaded policy's version** (a real, populated field), not "active
pack versions" as `UseCaseSummary`'s doc comment says — jurisdiction
packs still don't exist in this codebase (same unresolved deviation since
P3-C01). Policy version is the closest real, populated analog. If/when
packs land, this should be extended to also compare pack versions.

## Deliverables

1. **`src/store/role.ts`** (new) — `getRole(): string`, `setRole(role: string): void`,
   backed by `localStorage['aigate:role']`, default `'1LoD'`.
2. **`src/store/register.ts`** — `getUseCases()`/`getUseCase()` now compute
   `current_verdict_status`, `last_evaluated_at`, `policy_version_at_evaluation`,
   and `stale_assessment` (given an optional `currentPolicyVersion` param)
   by scanning each use case's audit trail via `audit.getAll()`.
3. **`src/components/RegisterView.tsx`** (new) — 1LoD view (own use
   cases, no filters, columns per §10.1); 2LoD view (all use cases, tier/
   track/stage filter chips, full-text search over name, columns per
   §10.2 including Submitter and Stale badge). "Policy updated" banner
   logic built per §10.2 (checks for a `re_evaluation_queued` event more
   recent than `verdict_produced` — dormant today since P6-C02 hasn't
   built the trigger yet, but the check itself is real, not stubbed).
4. **`src/App.tsx`** — sidebar "Register" nav item now switches the main
   view to `RegisterView.tsx` (simple `'intake' | 'register'` view state);
   role-switcher control added to the header.
5. **`src/components/IntakeFlow.tsx`** — `CURRENT_ROLE` constant replaced
   with `getRole()` calls at every use (submitted_by, attested_by,
   corrected_by).
