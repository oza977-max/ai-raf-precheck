# Build Prompt: P3-C01 — Evaluation Engine (8-step pipeline)

## Chunk Summary

Replace the P1-C01 hardcoded stub `evaluate()` with the real deterministic
8-step evaluation pipeline (`evaluation-engine.md §3`): jurisdiction pack
resolution, hard-line evaluation, track assignment, tier assignment,
jurisdiction overrides, invariant evaluation, control solving (stubbed —
`solvControls()` returns `[]` until P3-C02), and verdict assembly.

This is a **pure-internal-engine chunk** — `src/engine/*` has zero React/idb/
SDK imports (cross-cutting.md §7 rule 1). It is exercised end-to-end through
the existing `WalkingSkeleton.test.tsx` acceptance test (via `IntakeFlow.tsx`
already calling `evaluate()`), so **TDD-1 exempted: pure internal engine
module, no new user-facing surface — the pipeline's user-visible effect
(a real verdict instead of a hardcoded stub) is proven by re-running the
existing acceptance test, and new unit tests drive the internal logic.**

## Deliverables

1. **`src/engine/types.ts`** (extend, don't replace) — add:
   - `DataFlowGraph`, `InputNode`, `ProcessingNode`, `OutputNode`, `GraphEdge`
     per `intake-flow.md §4.2` (post build-prep-fix field names)
   - `Condition` type: `Record<string, ConditionValue>` where
     `ConditionValue = { gte: number } | { lte: number } | { in: unknown[] } | { not_in: unknown[] } | string | number | boolean`
   - Full `EvaluationResult` per `evaluation-engine.md §3.9` (replace the
     7-field P1-C01 stub): add `binding_constraint`, `binding_path` (already
     present), plus `conditions: VerdictConditions`, `policy_version: string`,
     `pack_versions: Record<string,string>`, `applied_overrides: AppliedOverride[]`,
     `confidence_caveats: ConfidenceCaveat[]`, `boundary_proximity: boolean`
2. **`src/types/verdict.ts`** (new) — `Verdict` (extends `EvaluationResult`
   with `id`/`use_case_id`/`living_status`/timestamps/`corrections`),
   `VerdictConditions`, `ConfidenceCaveat`, `AppliedOverride` per
   `evaluation-engine.md §3.9`. `Verdict` envelope fields are NOT populated by
   `evaluate()` — that's the caller's job (verdict-audit.md territory, later
   chunk). This chunk's `evaluate()` returns `EvaluationResult` only.
3. **`src/engine/jurisdiction.ts`** (new) — `resolveActivePacks()` (§3.2) and
   `applyJurisdictionOverrides()` (§3.6). Since no jurisdiction packs exist on
   disk yet (P2-C03 is human-led pack authoring, not yet built), this chunk's
   `resolveActivePacks()` returns `[]` for any jurisdiction with no loaded
   pack (spec-mandated warning-not-error behavior) — there is currently no
   loaded-pack source to wire in, so `applyJurisdictionOverrides()` is a
   pass-through (`finalTrack = baseTrack`, `finalTier = baseTier`,
   `appliedOverrides = []`) until a pack-loading chunk lands. Document this
   explicitly in the handover as a deviation, not a silent no-op.
4. **`src/engine/tier.ts`** (new) — `assignTier()` (§3.5): evaluate ALL tier
   rules, return the highest tier whose trigger fires (impact-dominant,
   order-independent — property test required). Default `Low` if none fire.
5. **`src/engine/track.ts`** (new) — `assignTrack()` (§3.4): evaluate track
   rules in order, first match wins (short-circuit). If none match, return
   `Result<never, EngineError>` with `kind: 'no-track-match'`.
6. **`src/engine/condition.ts`** (new) — the shared condition evaluator
   (`ADR-002`, `policy-schema.md §8`): `matchesCondition(condition: Condition, graph: DataFlowGraph): boolean`.
   **Field lookup is multi-node** (§3.7): flatten every field across all
   input/processing/output nodes plus top-level graph fields
   (`jurisdictions`) into one lookup — a condition on `field: "autonomy_level"`
   matches if ANY node in the graph has that field and it satisfies the
   operator. Within one condition object, all keys are ANDed (§3.2). Operators:
   `gte`, `lte`, `in`, `not_in`, bare equality (§8 ADR-002 — do not implement
   `and`/`or`/nested chains, the real `policy/appetite.yaml` never uses them;
   if a future policy needs them, that's a new ADR, not silent scope creep here).
7. **`src/engine/greedy-solver.ts`** (new, minimal stub only) — export
   `solvControls(trippedInvariants: string[], controlLibrary: Control[], inheritedControls: string[], margin: number): { ok: true; controls: string[] } | { ok: false; unsatisfiableInvariant: string }`.
   **This chunk's stub always returns `{ ok: true, controls: [] }` regardless
   of input** — P3-C02 replaces this with the real greedy algorithm
   (`evaluation-engine.md §4.2`). Do not implement the real algorithm here;
   that is explicitly P3-C02's scope per the dependency matrix.
8. **`src/engine/evaluate.ts`** (replace stub) — real 9-step pipeline
   (`evaluation-engine.md §3.1`, note the spec numbers jurisdiction-resolution
   as step 1 and hard-lines as step 2 — 9 steps total including verdict
   assembly, not 8 despite the implementation-guide chunk title):
   1. Resolve active jurisdiction packs (`resolveActivePacks`, currently `[]`)
   2. Evaluate hard lines (`evaluateHardLines`) — first trip → immediate
      `rejected`, `reason: 'hard-line'`, no further steps run
   3. Assign track (`assignTrack`) — `no-track-match` is an `EngineError`,
      not a rejection (policy misconfiguration)
   4. Assign tier (`assignTier`)
   5. Apply jurisdiction overrides (`applyJurisdictionOverrides`) — pass-through
      per deliverable 3
   6. Evaluate invariants (`evaluateInvariants`) — collect ALL tripped, no
      short-circuit
   7. Solve controls (`solvControls`, stub from deliverable 7)
   8. Determine status: `rejected` if hard line tripped OR solver
      unsatisfiable; `approved_with_controls` if invariants tripped AND
      solved; `approved` if no invariants tripped
   9. Assemble and return `EvaluationResult` (pure, no identity/time fields)

   `evaluate(graph: DataFlowGraph, policy: PolicyFile): Result<EvaluationResult, EngineError>`
   — note this CHANGES the P1-C01/P2-C01 signature from returning
   `EvaluationResult` directly to `Result<EvaluationResult, EngineError>`
   (only `no-track-match` produces an `Err`; everything else is a normal
   `Ok` verdict, including `rejected` verdicts — rejection is a valid
   verdict, not an engine error). **Upstream fix required**: update
   `IntakeFlow.tsx`'s call site to unwrap the `Result`.

## API Boundary Contracts

- `evaluate()` remains a pure function: no `Date.now()`, no `Math.random()`,
  no I/O, no LLM calls anywhere in the call graph (NF-1, §7).
- Before evaluation, sort `policy.hard_lines`, `policy.tracks`, `policy.tiers`,
  `policy.invariants`, `policy.controls` by `id` (§7.2) to eliminate YAML
  load-order non-determinism. Do this once at the top of `evaluate()`, not
  scattered across each step function.
- `src/engine/*` imports only from `./types` and stdlib — verify with
  `grep -rn "from 'react'\|from 'idb'\|@anthropic-ai/sdk" src/engine/` (must
  be empty).

## Framework Reference

pattern already established in `src/engine/types.ts` and the discriminated-
