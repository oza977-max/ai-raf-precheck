## Part B — PolicyEditor Save Flow

### Spec Drift / Design Decision

`register-lifecycle.md §8`'s `onPolicyUpdated()` signature returns
`Promise<void>`. For the Save flow's UX (a specific, honest "N use cases
queued for re-evaluation" confirmation message instead of a vague
"saved"), `onPolicyUpdated()`'s return type is widened to
`Promise<{ queuedCount: number }>` — a compatible, non-breaking change
(no existing caller used the return value; `policy.test.ts`'s existing
assertions on audit-event side effects are unaffected).

### Deliverables

1. **`src/store/policy-source.ts`** (new) — thin `localStorage` wrapper,
   same shape as `role.ts`: `getCurrentPolicyYaml(): string` (returns a
   stored override or the bundled starter YAML), `setCurrentPolicyYaml
   (yaml: string): void`. Centralizes "what YAML is currently active" so
   `App.tsx` and `IntakeFlow.tsx` read from one place instead of each
   independently importing the static starter file.
2. **`src/store/policy.ts`** — `onPolicyUpdated()` returns
   `{ queuedCount: number }`.
3. **`src/components/PolicyEditor.tsx`** — real Save flow: pre-fills the
   textarea with `getCurrentPolicyYaml()` on mount; "Save" button
   validates via `loadPolicy()`, and if valid, persists via
   `setCurrentPolicyYaml()`, calls `onPolicyUpdated(policy.version)`,
   shows "Policy saved — N active use case(s) queued for re-evaluation."
   (0 is a valid, honestly-reported count, not hidden), and calls an
   `onSaved` callback prop so the parent can react. If invalid, shows
   the same field-level error list the existing "Load" behavior already
   had (kept, unchanged) — no save attempted.
4. **`src/App.tsx`** — the "Appetite framework" sidebar item is no
   longer permanently disabled: it's a real third `view` state
   (`'policyEditor'`) routing to `PolicyEditor`. `policyResult`/
   `currentPolicyVersion` move from module-level constants (computed
   once at import time) to component state recomputed via a
   `policyRevision` counter, bumped by `PolicyEditor`'s `onSaved`
   callback — this is what makes a saved policy change immediately
   visible in the header's "policy vX.X" badge and in `RegisterView`'s
   `currentPolicyVersion` prop without a full page reload.
5. **`src/components/IntakeFlow.tsx`** — replaces its static
   `import appetiteYaml from '../../policy/appetite.yaml?raw'` +
   `loadPolicy(appetiteYaml)` with `loadPolicy(getCurrentPolicyYaml())`.
   Because `App.tsx`'s `view` ternary already unmounts/remounts
   `IntakeFlow` every time the user navigates away and back (existing
   behavior, not new), `IntakeFlow`'s own `useMemo(() => ..., [])` will
   naturally re-read the saved policy on the next visit — no additional
   prop-threading or context needed.

### API Boundary Contracts

- `policy-source.ts` — zero React/LLM imports, same shape as `role.ts`.
- `PolicyEditor.tsx` stays presentation-only: calls `loadPolicy()`,
  `setCurrentPolicyYaml()`, `onPolicyUpdated()` — no business logic
  inlined.

### TDD Approach

**TDD-1 applies.** Acceptance test first: `WalkingSkeleton.test.tsx` —
navigate to "Appetite framework," edit the policy version field in the
YAML, click Save, confirm the success message reports a queued count,
navigate back to the register/intake and confirm the header now shows
the new policy version. A second acceptance test: with an existing
active use case in the register, saving a policy update produces a
`re_evaluation_queued` audit event for it (real, not just a UI message).

Unit tests: `PolicyEditor.test.tsx` — invalid YAML shows errors and does
NOT call `setCurrentPolicyYaml()`/`onPolicyUpdated()`; valid YAML calls
both and reports the correct queued count; `onSaved` callback fires only
on success.

## Review Criteria

**Experts loaded:** Kent Beck (TDD), Fowler (state lifted correctly —
no stale-closure risk on `policyRevision`), McConnell (honest reporting
— the queued-count message must reflect reality, never a hardcoded
placeholder).

**Known Patterns to Avoid:**
- BC-P7C03-01: the Save flow must genuinely call the real
  `onPolicyUpdated()` (queuing real `re_evaluation_queued` audit events
  for real active use cases) — not a stubbed/simulated success message.
- BC-P7C03-02: an invalid YAML must never call `setCurrentPolicyYaml()`
  or `onPolicyUpdated()` — the existing error-display path must remain
  intact and gate the save.
- BC-P7C03-03: `IntakeFlow.tsx`'s remount-on-navigation reliance for
  policy freshness must be verified, not assumed — confirm via a test
  that actually navigates away and back, not just a unit test of the
  `useMemo` in isolation.
