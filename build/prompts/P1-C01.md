# Build Prompt: P1-C01 — Project scaffold + walking skeleton

## Chunk Summary

End-to-end wired boundary. No real business logic — but every external boundary is
exercised by a **real interaction with an observable outcome** (GVM walking-skeleton
rule, Ch. 12 of the Grounded Vibe Methodology). Proves the wiring works before any
domain chunk fills it in. This is also the MVP-1 tracer bullet: the user can type a
description, click through the intake wizard, see a hardcoded verdict, and view it in
the register — interactive and end-to-end, not a page template.

**Boundary registry (2 external boundaries, both wired for real in this chunk — no stubs):**
1. **persistence** — IndexedDB via the `idb` library: write one real row, read it back.
2. **network / third-party** — Anthropic API (`claude-sonnet-4-6`, `dangerouslyAllowBrowser: true`):
   one real `tool_use` call, inspect the structured JSON response. Test gated on API-key
   presence — skips cleanly (not fails) without one.

## Spec Excerpt

**From `cross-cutting.md §2` (Core library choices) — exact versions to install:**
```
idb ^8.0, @anthropic-ai/sdk ^0.39+, zod ^3.x, uuid ^9.x, zustand ^4.x, vitest + @testing-library/react (latest)
```

**From `cross-cutting.md §4` (TypeScript Standards):**
- Strict mode: `strict: true`, `noImplicitAny: true`, `strictNullChecks: true`
- Discriminated unions for domain status types (`VerdictStatus`, `Tier`, `Track`)
- No `any` — `unknown` + type guards for external data (YAML, LLM responses)
- Zod schemas at every external boundary — the schema IS the runtime validator AND the TS type source

**From `cross-cutting.md §5` (Error Handling — Result pattern, no exceptions in the evaluation path):**
```typescript
type Result<T, E = EngineError> =
  | { ok: true; value: T }
  | { ok: false; error: E };
```
LLM calls wrapped in try/catch, always return `Result<T, LlmError>`. Engine functions never throw.

**From `cross-cutting.md §7` (Module Boundary Rules) — hard constraint for this chunk:**
- Rule 1: `src/engine/*` imports only from `src/engine/types.ts` + stdlib TS types. No React, no idb, no Anthropic SDK.
- Rule 2: `src/llm/*` is the ONLY place the Anthropic SDK is imported.
- Rule 3: `src/store/*` is persistence-only — no evaluation logic, no LLM calls, no React imports.
- Rule 4: `src/components/*` is presentation-only — calls engine/store/llm functions, no business logic inline.
- Dependency direction: `components → store`, `components → engine`, `components → llm`. Never the reverse.

**From `cross-cutting.md §9` (API Key Management):**
Key lives in `localStorage['aigate:api-key']`, read at call time by `src/llm/client.ts`, never in React state,
masked input (`type="password"`) when a settings UI exists (not required this chunk).

**From `verdict-audit.md §4.4` (AuditStore — append-only discipline):**
```typescript
export interface AuditStore {
  append(event: AuditEvent): Promise<void>;
  getAll(useCaseId: string): Promise<AuditEvent[]>;
}
```
`db.add()` not `db.put()` — duplicate `event_id` throws `ConstraintError` rather than silently overwriting.
This chunk only needs a minimal `AuditEvent` shape to prove the boundary — full `AuditEventType` union
(`verdict_produced`, `graph_confirmed`, etc.) arrives in P2-C02/P4-C04. Use a minimal placeholder event
shape: `{ event_id: string; use_case_id: string; event_type: 'skeleton_test'; occurred_at: string }`.

**From `evaluation-engine.md §3.9` (EvaluationResult — pure result shape, no identity/time fields):**
```typescript
interface EvaluationResult {
  status: 'approved' | 'approved_with_controls' | 'rejected';
  tier: Tier;
  track: Track;
  binding_constraint: string;
  binding_path: string;
  controls: string[];
  downstream_reviews: string[];
  // conditions, policy_version, pack_versions, applied_overrides, confidence_caveats,
```

```typescript
interface AuditDB extends DBSchema {

const db = await openDB<AuditDB>('aigate-audit', 1, {
  upgrade(db) {
    const store = db.createObjectStore('audit_events', { keyPath: 'event_id' });
    store.createIndex('by_use_case', 'use_case_id');
```

## TDD Approach

This is a **user-facing chunk** (the wizard UI is Hard Gate 8's smoke surface) — the outside-in acceptance
test is the FIRST deliverable, per TDD-1.

**Realistic-fixture variant (TDD-3):** this chunk's domain is closest to "API" + "Concurrency" in the
catalogue (an external network call + an external storage call). Realistic-fixture variant test:
`extractGraphSkeleton` called with **no API key present** — must return `{ ok: false, error: { kind: 'no-api-key' } }`
cleanly, not throw. This is a named realistic-fixture shape (missing required credential), separate from the
happy-path test (API key present, call succeeds).

Ordering:

1. **Write the failing outside-in acceptance test FIRST** (`src/App.test.tsx` or
   `src/components/__tests__/WalkingSkeleton.test.tsx`):
   `describe('Walking Skeleton') → it('completes full flow end-to-end with real boundaries')` —
   renders the app, types a description, submits, asserts a verdict renders, asserts the register shows
   one row. Mock only the Anthropic SDK call itself (external boundary — TDD-2 mock budget = 1); use
   real `idb` via `fake-indexeddb`.
   Run → confirm **Red**. Capture the Red commit SHA.
2. For each unit-level deliverable the acceptance test now demands:
   a. Write failing unit test (boundary tests first: `db.test.ts` real write→read round-trip;
      `graph-extractor.test.ts` real `tool_use` shape parse + the no-api-key realistic-fixture variant)
   b. Write minimal code to pass (Framework Reference above)
   c. Run unit test → confirm pass
   d. Review against Review Criteria below (fix until clean)
   e. Refactor if needed → re-review
3. Run the acceptance test → confirm **Green**. Capture the Green commit SHA.
4. Commit: `feat: P1-C01 walking skeleton — real IndexedDB + real Anthropic boundary [P1-C01]`

**LLM boundary test note:** the real Anthropic call test should be conditionally gated —
if `process.env.ANTHROPIC_API_KEY` (or a test-only env var) is not present, the test SKIPS
(via `it.skipIf` / `test.skipIf` in Vitest) rather than failing. The no-api-key realistic-fixture
variant test does NOT need a real key — it tests the `localStorage`-empty path, which is fully
mockable at the `client.ts` boundary without ever calling the network.
