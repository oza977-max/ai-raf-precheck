# Build Prompt: P4-C01 — Intake Flow: LLM Graph Extraction + State Machine

## Chunk Summary

Replace `IntakeFlow.tsx`'s primitive 3-step P1-C01 wizard with the real
9-state machine (`intake-flow.md §3`), and replace `extractGraphSkeleton()`
(the trivial P1-C01 boundary-proof stub) with a real `extractGraph()` that
returns a full `DataFlowGraph` via forced tool-use. This is the first
**user-facing** chunk since P1-C01 — **TDD-1 applies, NOT exempted.** The
outside-in acceptance test is the first deliverable.

**Explicit P4-C01/P4-C04 boundary (per implementation-guide.md's chunk
split):** `questionnaire`, `contradiction_review`, and `confirmation` are
P4-C03/P4-C04's scope (question generation, contradiction detection, and
attestation don't exist yet). P4-C01's state machine includes all 9 states
in the type (so downstream chunks build against the locked union, not a
narrower one) but the UI's `graph_review → questionnaire → ... →
evaluation_pending` path is a **documented direct pass-through**: after the
user proceeds from `graph_review`, the flow goes straight to
`evaluation_pending` (skipping the not-yet-built middle states), calls
`evaluate()` (already real, P3-C01/C02), and lands on `verdict`. This keeps
the acceptance test's full description→verdict path exercisable end-to-end
while being honest that UC-4/UC-5/UC-6 aren't wired yet. Record this
explicitly in the handover — it is the same "documented pass-through"
pattern already used for P3-C01's jurisdiction-override stub.

## Deliverables

1. **`src/engine/types.ts`** (extend) — add `GraphCorrection` interface
   (`intake-flow.md §8`) — pure data type, belongs with `DataFlowGraph`.
2. **`src/components/intake-state.ts`** (new) — `IntakeState` discriminated
   union (exact shape from `intake-flow.md §3`, all 9 states),
   `IntakeAction` union, and a pure `intakeReducer(state, action): IntakeState`
   function — kept separate from `IntakeFlow.tsx` so the state machine is
   independently unit-testable without React Testing Library.
3. **`src/engine/duplicate.ts`** (new) — pure keyword-overlap duplicate
   check: `findPossibleDuplicates(description: string, existing: {id: string; label: string}[]): {id: string; score: number}[]`.
   Jaccard word-overlap similarity, threshold 0.4 (documented judgment call
   — spec doesn't name a precise threshold). No I/O, no LLM — this is the
   always-available fallback (UC-2).
4. **`src/llm/graph-extractor.ts`** (replace) — `extractGraph(description, apiKey, policyPermittedValues): Promise<Result<DataFlowGraph, LlmError>>`
   per `intake-flow.md §4.1/§4.3/§4.4/§10`. Forced tool-use
   (`tool_choice: { type: 'tool', name: 'extract_graph' }`), hand-written
   JSON schema mirroring `DataFlowGraph` (no new `zod-to-json-schema`
   dependency — the schema is small enough to hand-write, same approach
   `graph-extractor.ts`'s existing skeleton stub already uses). Response
   parsed and validated with a Zod schema matching `DataFlowGraph`; parse
   failure returns `{ ok: false, error: { kind: 'parse-error', raw } }`.
   Nodes the LLM can't determine confidently are marked `uncertain: true`
   (LLM's own judgment, prompted for explicitly).
5. **`src/llm/duplicate-check.ts`** (new) — `confirmSemanticDuplicate(description, candidateLabel, apiKey): Promise<boolean>`.
   Only called when `findPossibleDuplicates()` already flagged a
   keyword-overlap candidate AND an API key is present (UC-2's "semantic
   comparison when API key present" — this is a confirmation step on top
   of the keyword fallback, not a replacement for it).
6. **`src/components/IntakeFlow.tsx`** (replace) — real 9-state wizard using
   `intakeReducer`. Renders: description entry → duplicate check (keyword
   always, LLM confirmation if API key present) → graph extraction (LLM or
   graceful no-key message, since P4-C02 hasn't built the structured-form
   fallback UI yet — a documented gap, not silently ignored) → graph review
   (node list, `uncertain: true` nodes visually flagged, Edit button per
   node opening a correction form) → **pass-through to evaluation_pending**
   → verdict. Corrections recorded via `GraphCorrection`, increment
   `graph.version`, written to the audit trail via `audit.append()`
   (`event_type: 'graph_confirmed'` is NOT written here — that's P4-C04's
   attestation scope; this chunk's audit write, if any, should not
   pre-empt P4-C04's confirmation semantics — if in doubt, skip the audit
   write for corrections in this chunk and flag it as a P4-C04 dependency
   in the handover rather than guessing at semantics not yet specified).

## API Boundary Contracts

- `src/llm/*` remains the ONLY Anthropic SDK importer (cross-cutting.md §7
  rule 2) — verify `grep -rln "@anthropic-ai/sdk" src/` returns only files
  under `src/llm/`.
- `src/engine/duplicate.ts` has zero I/O, zero LLM — same purity rule as
  the rest of `src/engine/*`.
- No API key → `extractGraph()` returns `{ ok: false, error: { kind: 'no-api-key' } }`,
  same shape as the existing `extractGraphSkeleton()`'s no-key path — the
  UI must handle this gracefully (message, not a crash), since P4-C02's
  structured-form fallback isn't built yet in this chunk.
