# Build Prompt: P4-C03 — Question Generation + Contradiction Detection

## Chunk Summary

Wires the real `questionnaire`/`contradiction_review` states (typed since
P4-C01, never rendered) into the flow: after graph review, generate
targeted questions from uncertain fields and tripped invariants/hard
lines; after each answer, run a contradiction check; block advancing
while any contradiction is unresolved. User-facing — **TDD-1 applies.**

**P4-C03/P4-C04 boundary**: this chunk still doesn't build real
confirmation/attestation (`intake-flow.md §9` — that's P4-C04, which also
owns writing the `graph_confirmed`/`verdict_produced` audit events). Once
all questions are answered and no contradiction remains, the flow proceeds
straight to `evaluation_pending` — the pass-through moves from
`graph_review` (P4-C01) to `questionnaire` (this chunk), not removed yet.

## Type Relocation (small refactor, not a deviation)

`IntakeQuestion`, `Contradiction`, `QuestionAnswer` currently live in
`src/components/intake-state.ts` — a UI-layer file. But
`question-generator.ts`/`contradiction.ts` are `src/engine/*` modules that
must return these types, and `src/engine/*` must never import from
`src/components/*` (one-way dependency, cross-cutting.md §7). Moving these
three types into `src/engine/types.ts` and having `intake-state.ts` import
them (not redefine them) fixes the direction before it becomes a problem.

## Documented Judgment Calls (spec is underspecified here — recorded up
## front, not discovered mid-review)

1. **"Worst-case" provisional tier** (§6): the spec says uncertain fields
   should be "treated worst-case" for the budget-determining tier pass.
   Since `extractGraph()`'s own prompt already instructs the LLM to "make
   a reasonable best-guess value anyway" even on uncertain nodes (P4-C01),
   every uncertain field already carries a concrete value, not a hole.
   **This chunk uses the graph's already-extracted values directly**
   (no separate worst-case substitution engine) — a real worst-case
   engine would need per-field ceiling values for every enum, which is
   scope this chunk doesn't take on. Flag in the handover as a real
   simplification, not silently absorbed.
2. **`activePacks: JurisdictionPack[]` parameter**: no pack-loading chunk
   exists yet (same P3-C01 deviation, still unresolved). `JurisdictionPack`
   gets a minimal placeholder type (`{ code: string; rules: [] }`) in
   `engine/types.ts`; `generateQuestions()` always receives `[]` from the
   caller, so pack-triggered questions (§6 selection logic step 3) never
   fire. Documented, not silently dropped.
3. **`detectContradictions()`'s field-linkage gap**: the spec's signature
   (`description, answers, graph`) doesn't give the function access to
   which graph field each `QuestionAnswer` targeted — only `questionId`.
   True answer-vs-answer field contradiction detection isn't possible from
   this signature alone. **Scoped down to description-vs-graph contradiction
   only** (the spec's own Pattern 1 example: "description says X, extracted
   graph says not-X") via a small fixed table of known signal pairs — not
   a general NLP solution. This is deterministic and engine-appropriate
   (no LLM), consistent with `intake-flow.md §2`'s "LLM at input edge only"
   ASR.

## Deliverables

1. **`src/engine/types.ts`** (extend) — relocate `IntakeQuestion`,
   `Contradiction`, `QuestionAnswer` here; add minimal `JurisdictionPack`
   placeholder type.
2. **`src/components/intake-state.ts`** (modify) — import the three
   relocated types instead of defining them; extend `IntakeAction` with
   `QUESTIONS_GENERATED`, `ANSWER_SUBMITTED`, `CONTRADICTIONS_DETECTED`,
   `CONTRADICTION_RESOLVED`; wire real reducer transitions
   `graph_review → questionnaire → (contradiction_review ⇄ questionnaire) → evaluation_pending`.
3. **`src/engine/question-generator.ts`** (new) — `generateQuestions(graph, policy, activePacks)`
   per §6: tier-based budget (Low→5, Medium→10, High/Critical→15),
   prioritized by `triggered_by.length` descending, deduplicated by
   `field`+`node_id`.
4. **`src/engine/contradiction.ts`** (new) — `detectContradictions(description, answers, graph)`
   per the scoped-down interpretation above — fixed table of 2-3 known
   description-vs-graph signal pairs (client-data negation vs `data_class`,
   autonomy negation vs `autonomy_level`), matching `intake-flow.md §5`'s
   own listed examples.
5. **`src/components/QuestionnaireStep.tsx`** (new) — renders questions,
   each answer dispatches `ANSWER_SUBMITTED`, then `IntakeFlow.tsx` runs
   `detectContradictions()` and dispatches `CONTRADICTIONS_DETECTED` if any.
6. **`src/components/ContradictionReview.tsx`** (new) — shows conflicting
   statements, requires resolution (a text explanation or acknowledgment)
   before `CONTRADICTION_RESOLVED` can be dispatched.
7. **`src/components/IntakeFlow.tsx`** (modify) — wire the two new
   components into their states; move the pass-through trigger.

## API Boundary Contracts

- `question-generator.ts`/`contradiction.ts` have zero I/O, zero LLM — same
  `src/engine/*` purity rule.
- Deterministic: `generateQuestions()` must return identical output across
  repeated calls with the same inputs (sort before any array iteration that
  affects output order, same NF-1 discipline as `evaluate()`).

## TDD Approach

first (uncertain node → question rendered → answered → verdict reached),

## Review Criteria

**Experts loaded:** Alan Cooper (goal-directed — minimal friction even
with mandatory questions), Kent Beck (TDD), Stuart Russell (autonomy
signals must be clearly surfaced — this chunk is literally about surfacing
uncertain autonomy/data signals as questions).

**Known Patterns to Avoid:**
- BC-P4C03-01: `src/engine/*` must not import from `src/components/*` —
  verify the type relocation actually fixed the direction, don't just add
  a new engine file that re-imports from intake-state.ts out of habit.
- BC-P4C03-02: question budget must be enforced by trimming lowest-priority
  candidates, not by generating fewer candidates in the first place (which
  would silently change which questions get asked based on iteration order
  rather than genuine priority).
- BC-P4C03-03: contradiction resolution must genuinely block the
  `CONTRADICTION_RESOLVED`/advance action until a real resolution value is
  provided — an empty/no-op resolution must not silently pass.
