# Build Prompt: P8-C02 — Required-field markers

## Chunk Summary

Every field whose absence disables Continue on the guided intake form carries
both a visible required-marker and `aria-required="true"`. The two sets — fields
that block progress, and fields that are marked — must be identical in both
directions. Optional fields (platform, vendor, decision type, human-in-the-loop)
carry neither.

Per `intake-flow.md` §13.3 and design review round 1 finding I-8, a **single
required-field list is the source of truth**: `isComplete` derives from it, the
markers render from it, and the test reads it. That refactor is budgeted into
this chunk; it is not incidental work.

## Spec Excerpt

`intake-flow.md` §13.3 (verbatim):

> Every field whose absence disables Continue carries **both** a visible
> required-marker and `aria-required="true"`. The two sets — fields that block
> progress, and fields that are marked — must be identical in both directions
> (TC-R3-JU-5-01). Marking every field, including the optional platform and
> vendor selects, fails the requirement as surely as marking none: it tells the
> user nothing.
>
> **Design review round 1, I-8.** `isComplete` is a hand-written boolean
> conjunction, so "the set of fields that block progress" is not enumerable and
> the test cannot check set equality without hardcoding the same list a second
> time — recreating, in test code, exactly the un-synced duplication this
> requirement exists to prevent. A single required-field list is therefore the
> source of truth.

Requirement R3-JU-5 (Should) — also closes charter 004 D-003: *a disabled
Continue with nothing naming the outstanding field.*

Cross-cutting §7 rule 4: `src/components/*` is presentation-only.

## Test cases

- **TC-R3-JU-5-01** — the set of progress-blocking fields and the set carrying

- **TC-R3-JU-5-02** — the optional platform and vendor fields carry no marker

## Framework Reference

- React 18 — controlled inputs; `aria-required` is passed through to the DOM
  verbatim by JSX (any `aria-*` prop is rendered as-is, unlike camelCase DOM
  props).
- Testing Library — `container.querySelectorAll('[aria-required="true"]')`
  returns the marked set; `getByRole('button', { name: /continue/i })` and
  `toBeDisabled()` establish the blocking set field-by-field.
- ARIA note: `aria-required` is defined for form controls, not for `group`. The
  jurisdiction question is a fieldset of checkboxes, so the attribute goes on
  the fieldset with the visible marker in the legend; this is a deliberate,
  recorded compromise rather than an oversight — there is no ARIA-conformant
  attribute for "this checkbox group must be answered".

## TDD Approach

User-facing chunk — TDD-1 applies. The outside-in acceptance test is the first
deliverable.

1. **Acceptance test first:** TC-R3-JU-5-01 — drive the form to the state where
   Continue is disabled, enumerate the blocking set by clearing one field at a
   time, and assert set equality against the marked set. Confirm **Red**, record
   the SHA.
2. Extract `REQUIRED_FIELDS`; derive `isComplete`; render the markers.
3. TC-R3-JU-5-02 — optional fields unmarked.
4. **Realistic-fixture variant (TDD-3, web/UI domain):** a pre-round-3 legacy
   draft restored from session storage that lacks the defaulted keys
   (`autonomyLevel`, `replacesPriorModel`). This is the shape the engineer's
   happy path does not produce, and it is the one where a field can be
   unanswered with no marker to say so.
5. Confirm **Green**, record the SHA.

## Review Criteria (self-review loop — not construction)

- **One enumeration, three readers** (Metz/McConnell). If the test can pass
  while the list and the gate disagree, the refactor did not land.
- **Beck:** would the acceptance test pass against the pre-chunk code? If yes,
  it is not the test.
- **Honesty (CLAUDE.md / NF-2):** a required-marker on a field that is
  pre-filled and can never block is a claim the UI cannot support. Do not mark
  what does not block.
- **Verdict-query collision (HR3-08):** no new rendered string may contain the
  words "approved" or "rejected".
- Determinism (NF-1) is not touched by this chunk — no engine changes.
