Findings

CRITICAL · src/engine/track.test.ts:114 FIXED

Expert: Kent Beck / Boris Beizer

Issue: The track-totality assertion read if (!assignTrack(g, tracks)). assignTrack returns a Result OBJECT ({ok:true,value} or {ok:false,error}), which is always truthy, so the unrouted array could never be populated and expect(unrouted).toEqual([]) passed against ANY policy. Proven empirically: TRACK-I was deleted from policy/appetite.yaml — stranding statistical and traditional-ml at autonomy<3 — and all 4 tests still reported passed. With the .ok fix applied to the same broken policy the test goes red. This test was written specifically to guard the defect class that had already shipped twice (oracle rounds 001 and 002 both found track-routing holes), and it guarded nothing. Its green tick was cited in the policy file comments, the commit message, and backtest/oracle-round-002.md as evidence of totality.

Fix applied: condition corrected to .ok, plus a new mutation-guard test that deliberately breaks the routing and asserts the checker notices — so the totality check can never silently go vacuous again.

CRITICAL · README.md:7, :80, :90

Expert: honesty-triad Panel E

Issue: README still advertises OSFI E-23, MAS FEAT and FSA Japan as active jurisdiction packs in three separate places. All three pack files were deleted in this range for carrying "[ILLUSTRATIVE — NOT VERBATIM]" rule text with "[NOT RETRIEVED]" source dates. A bank risk officer reading the README — the first document any evaluator opens, on a PUBLIC repository — would believe Canada, Singapore and Japan use cases receive real jurisdictional coverage. The engine and the Appetite view both handle this correctly (PolicyEditor renders "declared — no pack file loaded"), so the code is honest and the documentation is not.

Fix: reduce the three lists to the four surviving packs (SS1/23, EU AI Act, SR 26-2, DORA) and state that CA/SG/JP are declared operating jurisdictions with no assessed pack.
