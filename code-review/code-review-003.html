2. The finding that matters most

From the blind reviewer, who was given the codebase and the product's own framing and nothing else:

The engine and its honesty machinery are trustworthy. The human sign-off step that the whole "legal weight" claim rests on is not.
The 2LoD attestation has no identity behind it — HELD, not fixed

The role is a dropdown. src/store/role.ts reads it from localStorage with no credential check. Anyone can select "2LoD" and approve anything, including a use case they submitted themselves — there is no segregation-of-duties check against submitted_by. And the audit trail writes actor: role (RegisterDetail.tsx:135,168), so the record says "2LoD", not a person. After the fact the append-only trail cannot say who signed.

The product states its other limits plainly and unprompted — client-side storage, proof-of-concept grade, unsigned pack rules, unattested translation fidelity. It says nothing about this one. Everything downstream of the sign-off is honest; the sign-off itself is the gap between "AIGate reasons correctly" and "AIGate can prove who accepted that reasoning".

3. Findings fixed

A failed LLM extraction was a dead end

With an API key configured, a failed extractGraph call set an error and returned without dispatching. The screen kept rendering "Extracting graph…" with the error beneath it — a label still claiming work was in progress. No retry, no way back, and a reload restored the same stuck step from the draft. Fixed: retry and start-over offered, and the progress label no longer shows once the attempt has failed.

src/components/IntakeFlow.tsx — Panel C (Logic & Completeness)

Round 4 added an audit write to handleConfirmNewUseCase and did not add the synchronous in-flight guard its two siblings in the same file already have — one of them fourteen lines away. state.step is read from the render closure, so a second click before re-render passes the same check. Two duplicate_dismissed events land in an append-only trail that cannot be corrected. Fixed, with a two-clicks-in-one-tick test.

src/components/IntakeFlow.tsx:192 — Panel E (Concurrency & Ordering)
Traceability computed, then discarded — the V1 citation defect, repeated

firmRequiredReviews returns rule_id and regulatory_basis precisely so a reviewer can check which policy rule required an obligation. All three call sites did .map(r => r.review) and threw both away before the verdict. A test asserted the function returned them; nothing asserted a reader ever saw them. This is the same defect class that lost this product its regulatory citations for the whole of V1, committed in the chunk that introduced the feature. Fixed: the verdict carries downstream_review_sources and the screen renders "Information security review — required by DR-INFOSEC-02" with its citation. Confirmed live.

src/engine/evaluate.ts:98,214,280 — Panel B (Contracts & Interfaces)
An attestation pointing at nothing

Both sign-off writers used verdict_id: latestVerdict?.id ?? ''. With no verdict recorded, the write produced an attestation that satisfies the type and resolves to no verdict — reopening the hole P8-C08 added the field to close. Fixed: the write is refused with a reason the reviewer can act on, and the guard now returns the verdict being attested to so the type carries the guarantee rather than an optional chain.

src/components/RegisterDetail.tsx:139,172 — Panel B
