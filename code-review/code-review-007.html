2. Headline

The round-6 fix for "Back removes the guessed-value safety check" (CR6-03) closed Back’s gate fields but not the two other ways back into the review screen, and not the answers themselves. Three panels and a checker’s probe agree: on the description path, "Change an answer", a failed evaluation, and Back from the questions all lose the person’s "Not sure" assumptions, so the confirmation summary and the signed attestation present the case as firmer than it is. In one sequence ("Not on this list", then Back before typing the name) the AI’s rejected supplier guess reaches the result unasked. The same pattern — a safety or honesty field carried on one step and dropped on a return path — is the calibration’s candidate RF-9, now in its fourth consecutive round.

Second headline: the audit trail — the product’s evidence store — forks when a reviewer uses two tabs. Each tab caches the last hash; the cross-tab lock orders the writes but never refreshes it. A checker proved it with two module instances over one database: verifyChain() then reports "prev_hash does not match" on data nobody tampered with, permanently.

What held: the CR6-01 hand-off fix (a calibrated panel exported and re-imported every seeded case and a maximal real assumption payload — all imported, chain intact); the CR6-02 Start-over guards; ENG-ID; the reserved-word sweep of copy; output safety (no dangerouslySetInnerHTML anywhere); every "Not sure" mapping in plain-intake.

CR7-03 — Important (owner may judge Critical)
Back from the questions loses the "Not sure" answers, and in one sequence keeps the AI’s rejected guess.

File: src/components/intake-state.ts:514-540 (STEP_BACK), :778-788 (answers trim the guessed list, including "Not on this list"); IntakeFlow.tsx:1650-1675.

Impact: (1) "Not sure" → Back → Continue: the field is not asked again and the assumption is gone from the result (probe: "re-asked? false", result mentions unsure answers: false). 9. What prevents a higher score

  • Safety and honesty fields dropped on return paths (CR7-02, 03): the fix pattern is per-transition, not a property of the state type — the class will recur until the review step’s type requires them.
  • Cross-tab correctness (CR7-05, 18) has no test harness: jsdom has no navigator.locks and one module instance per test, so nothing can see a second tab. Structural until a two-instance test pattern exists.
  • Docs and spec twins are outside every mechanical check (CR7-12, 32, 33, O-7): spec-parity reads .md only; nothing reads docs/.
  • Contrast is unchecked by any test (CR7-08): a token-level test would close it permanently.
