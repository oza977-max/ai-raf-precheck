6. Critical findings (CR6-01–06)

CR6-01 — Critical
Hand-off import reports every real case as "tampered"

File: src/store/handoff.ts:698,733 (verifyChainOf on parsed events) + audit.ts:79-81 (eventContent hashes JSON.stringify(payload)) vs IntakeFlow.tsx:1229-1251 / evaluate() key order.

Impact: The two-person/two-machine hand-off (RG-8) cannot move any real case, and tells the user the file was tampered with — a false integrity claim. Pre-existing since 3e4f119, 2026-09-28; live. Found by B blind; proven by chair test.

Fix: Validate shape with the schema but verify the hash chain and store the RAW events as written (never a re-serialised copy); add a round-trip test with an app-written case (real evaluate() verdict + verdict_corrected in writer order).

Recommend: fix (release blocker).

Disposition: Fix — owner decision, 2026-10-03

CR6-02 — Critical
"Start over" leaves earlier work running

File: IntakeFlow.tsx:104-125 resets only confirmInFlight; dupCheckInFlight/confirmNewInFlight/retryExtractionInFlight/adoptInFlight stay set; duplicate-check effect has no cancellation (:370-415). The "Start over instead" banner stays visible on every step after a reload.

Impact: Next case’s Continue / Try again / Use the earlier result silently do nothing until the old call settles (local model up to 120 s; Anthropic minutes); an abandoned duplicate check’s result can appear on the new case and could be adopted. (Chair: an abandoned extraction cannot land on the new case — the reducer only accepts it on the extraction step, which the new case can’t reach while blocked.) Pre-existing refs, in a function this range edited.

Fix: Reset every in-flight guard in handleStartOver; cancellation flag on the duplicate-check effect (the precedents effect’s pattern).

Recommend: fix.

Disposition: Fix — owner decision, 2026-10-03

CR6-03 — Critical
Going Back from the questions removes the guessed-value safety check

File: intake-state.ts:438-448 rebuilds graph_review without guessedFields/unconfirmedNodeIds/provenance/jurisdictionsConfirmed/ignoredJurisdictions; IntakeFlow.tsx:721 then regenerates questions with guessedFields ?? {}.

Impact: A value the AI guessed (no quote from the description) can reach the result without the person ever being asked; the review screen also drops its quotes and confirm gate and labels every value "Not in your description". Pre-existing gap in a case this range edited.

Fix: Carry those fields through Back (and EVALUATION_FAILED/CHANGE_ANSWER re-entries), or fail safe.

Recommend: fix.

Disposition: Fix — owner decision, 2026-10-03

CR6-04 — Critical
Undo crashes the app for a question session saved before today’s update

File: intake-state.ts:683-694 reads undo.questions/assumptionsLen (new in 9348882); old drafts have {graph, correctionsLen}; intake-draft.ts:39-50 checks only step; QuestionnaireStep.tsx:118 indexes undefined; no error boundary. Reload does not clear the bad draft.

Impact: User has a saved session in the browser from before today; they click Undo; app crashes. Found by B blind; V1 confirmed.

Fix: Default the missing fields on restore (one line) and add an error boundary.

Recommend: fix.

Disposition: Fix — owner decision, 2026-10-03

CR6-05 — Critical
"Does it replace something you already use?" is decided by the AI’s unchecked guess on the description path

File: graph-extractor.ts:84 requires it; QUOTE_FIELDS (:255-268) omits it, so it is never marked guessed, never asked, never shown as assumed (UnderstoodSummary.tsx:230-233 states it flatly) — yet TRACK-II-REPLACE (appetite.yaml:279-286, short_circuit) routes the case on it. The form asks it (Q12, Not sure → yes).

Impact: A critical routing decision is never reviewed; the person approves a verdict routed by an unquoted guess. Pre-existing root, new false coverage claim. Found by A calibrated; V2 confirmed.

Fix: Add to QUOTE_FIELDS so an unquoted value becomes a question; test.

Recommend: fix.

Disposition: Fix — owner decision, 2026-10-03

CR6-06 — Critical
Saved answers that no longer match the current options skip the "stricter reading, listed back" rule

File: plain-intake.ts:143-144, 186-190, 247-251 (stale supplier/assistant/platform → "weren’t sure" wording, no assumption; platform → Zone A); :293-295, 420-424, 442-445, 514-517 (Q4/Q6/Q7/Q12 unrecognised → least strict, no assumption); StructuredForm.tsx:329-335 accepts any non-empty value.

Impact: Reachable: edit the policy mid-case in the app’s policy editor, or a saved form across a release that changes options. Found by D blind + C blind; V2 confirmed.

Fix: Unrecognised values take the "Not sure" path (strictest + listed back); isAnswered validates against current options.

Recommend: fix.

Disposition: Fix — owner decision, 2026-10-03
