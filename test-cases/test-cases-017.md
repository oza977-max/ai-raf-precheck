## Track order fix

`src/engine/evaluate.ts` sorted `policy.tracks` by id before calling
`assignTrack()`, which is first-match/short-circuit over the array in the
order it is GIVEN (`src/engine/track.ts`; `specs/evaluation-engine.md` §3.4).
`policy/appetite.yaml` declares its track rules in a deliberate order —
`TRACK-III-AGENTIC` / `TRACK-II-REPLACE` / `TRACK-II-AUTONOMY` first, so those
special cases win before the general `TRACK-III`/`TRACK-I`/`TRACK-II` rules
beneath them — and id-sorting silently defeated it. 90 of 280 combinations of
model type × autonomy (0-4) × decision bindingness × `replaces_prior_model`
routed to the wrong track as a result.

| ID | Asserts |
|---|---|
| TC-R17-TO-01 | A statistical/traditional-ml model is Track II, not Track I, when it replaces a prior model or acts at autonomy ≥ 3 — `track.test.ts` |
| TC-R17-TO-02 | An llm/generative-ai model with non-binding output is Track III, not Track II; the same model at any other bindingness is still correctly Track II — `track.test.ts` |
| TC-R17-TO-03 | An agentic model is Track III, not Track II, even when it replaces a prior model or acts at autonomy ≥ 3 — `track.test.ts` |
| TC-R17-TO-04 | `evaluate()` assigns the same track as `assignTrack(graph, policy.tracks)` in the policy file's own order, over the full 280-combination model_type × autonomy × bindingness × replaces_prior_model space (hard-line short-circuits excluded, as documented — track assignment is honestly skipped there) — `track.test.ts` |
| TC-R17-TO-05 | Anti-vacuity guard: the OLD id-sorted order disagrees with the policy file order on exactly 90 of the 280 combinations, so TC-R17-TO-04 could not have passed vacuously — `track.test.ts` |

## Policy v1.6

Three owner-approved rule changes in `policy/appetite.yaml` (version `"1.5"`
→ `"1.6"`; see the file's own CHANGE LOG header for the full rationale):

(a) `INV-DISCLOSE-01` and `INV-ESCALATE-01` gain
`action_type: {in: [inform, execute, trade, approve]}` — narrowed to AI that
deals with a client directly, so an email a relationship manager edits and
sends under their own name no longer trips either.
(b) `INV-CITE-01`'s `model_type` narrowed from `[llm, generative-ai, agentic]`
to `[llm, agentic]` — image/audio/video/code generators dropped, since
"every statement carries a citation" has no meaning for them.
(c) `INV-SEC-01`'s description reworded to match its condition (an
output-reach story); the condition itself is unchanged.

| ID | Asserts |
|---|---|
| TC-R17-PV-01 | INV-DISCLOSE-01 and INV-ESCALATE-01 no longer trip when the AI only drafts or recommends for a human to send (action_type `draft`/`recommend`); both still trip when the AI deals with the client directly (action_type `inform`) — `evaluate.test.ts` |
| TC-R17-PV-02 | INV-CITE-01 still covers llm and agentic (AI that writes text) but no longer generative-ai (image/audio/video/code generators) — `evaluate.test.ts` |
| TC-R17-PV-03 | INV-SEC-01 still trips exactly as before (deep-learning/llm/generative-ai/agentic, exposure beyond the team's own) — regression guard proving the v1.6 description reword carried no condition change — `evaluate.test.ts` |
| TC-R17-PV-04 | The shipped policy's `version` field is `"1.6"` — `evaluate.test.ts` |
