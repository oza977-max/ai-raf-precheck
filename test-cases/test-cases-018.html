Reusing an identical, already-proven code shape at the second site was judged lower-risk than the cost of a second full end-to-end harness.
  • The downstream backtest re-run (npm test, which runs backtest-corpus.test.ts and backtest-predictions.test.ts) found zero worked cases whose downstream_reviews changed — backtest/engine- verdicts.json is byte-identical before and after this chunk (git diff confirms it), because none of the four shipped packs (policy/packs/*.yaml) defines a hard_line effect, so the pack hard-line bug fix (TC-R16-A1-42) has no real corpus case to move. This is the expected outcome stated in the contract (§1.3: "expected: only pack-hard-line rejections, which now list reviews") — there are none in the real corpus today, so no pinned expectation in backtest/use- cases.md or backtest/corpus.md needed updating.
  • Token rendering (@submitter/@model_owner) and placeholder resolution ({audience}/{destination}) are explicitly out of scope for this chunk (chunk D1's view-model) — checkPolicyReferences validates which tokens/placeholders are legal, never resolves one, and no test here asserts resolved output.
