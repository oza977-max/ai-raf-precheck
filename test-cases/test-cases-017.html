Track order fix

src/engine/evaluate.ts sorted policy.tracks by id before calling assignTrack(), which is first-match/short-circuit over the array in the order it is GIVEN (src/engine/track.ts; specs/evaluation-engine.md §3.4). policy/appetite.yaml declares its track rules in a deliberate order — TRACK-III-AGENTIC / TRACK-II-REPLACE / TRACK-II-AUTONOMY first, so those special cases win before the general TRACK-III/TRACK-I/TRACK-II rules beneath them — and id-sorting silently defeated it. 90 of 280 combinations of model type × autonomy (0-4) × decision bindingness × replaces_prior_model routed to the wrong track as a result.

Policy v1.6

Three owner-approved rule changes in policy/appetite.yaml (version "1.5" → "1.6"; see the file's own CHANGE LOG header for the full rationale):

(a) INV-DISCLOSE-01 and INV-ESCALATE-01 gain action_type: {in: [inform, execute, trade, approve]} — narrowed to AI that deals with a client directly, so an email a relationship manager edits and sends under their own name no longer trips either. (b) INV-CITE-01's model_type narrowed from [llm, generative-ai, agentic] to [llm, agentic] — image/audio/video/code generators dropped, since "every statement carries a citation" has no meaning for them. (c) INV-SEC-01's description reworded to match its condition (an output-reach story); the condition itself is unchanged.
